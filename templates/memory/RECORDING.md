# RECORDING.md — continuous recording

Read this after `AGENTS.md` when `.memory/config.json` says `"recording": "continuous"`. It replaces the
`knowledge/` rule of AGENTS.md §2, and §6 and §7: there is no periodic sweep. **Whoever records a fact
ingests it, in the same push** — the touched pages, the log and the index — and a check that costs no
tokens refuses the push until the record holds.

## 1. The layers

- **Raw:** the member's note, `members/<member>/notes/<date>-<slug>.md` — their words, claim lines with
  `by:` and `source:`. Never edited after ingest; a correction is a new note. Archived documents live in
  `knowledge/sources/`, verbatim.
- **Record:** `knowledge/wiki/entities/`, `knowledge/wiki/topics/`, `knowledge/people/` — one subject per
  page. Any member may write here, but only by ingest.
- **Index:** `knowledge/index.md` — its page list is generated by `node tools/ingest.js index`; never by hand.
- **Log:** `knowledge/log.md` — one entry per ingest, fix or lint, appended by `node tools/ingest.js log`.

## 2. Recording a fact

1. `node tools/sync.js` — pull first.
2. Write the note in `members/<member>/notes/`.
3. Update every page the note touches. Search the index and the pages first — never a second page for a
   subject that has one. Copy each claim line **verbatim**; a claim line travels as it is.
4. When the note contradicts a claim already there: a measurement, or a later decision by whoever holds that
   responsibility, strikes the older line (`~~…~~`) with `superseded:` naming the new one. Anything else keeps
   both lines and opens a question (`questions/`, AGENTS.md §4) to the older claim's `by:` member. Never
   decide another member's claim away.
5. `node tools/ingest.js log --op ingest --title "<what was recorded>" --source <the note> --touched <page,page>`
   (pages relative to `knowledge/`). A correction with no new note is `--op fix`, with the page as source.
6. `node tools/sync.js --push` — it regenerates the index, stages `knowledge/` with your folder, runs
   `node tools/ingest.js check`, and only then prints the push notice (AGENTS.md §3).

The check refuses: a log entry not in your name; a source or touched page that does not exist; a changed
page no log entry names (no silent edits); a claim line of the source missing from `knowledge/`; a stale
index; a malformed claim line or a broken link on a touched page. Fix what it names, run it again.

## 3. When two members wrote the same lines

`sync.js` exits 4 and names the files: someone pushed a change to the same lines first. Nothing is half
done — the rebase was aborted and your commit is kept. Run `node tools/sync.js --redo`: the clone takes the
remote's state, your commits stay on a `redo-…` branch, your own files come back, and it prints the notes
to re-apply. Apply each onto the fresh page (§2 steps 3–6). Never merge a page by hand, never pick a side.

## 4. The inbox, and what is left of the sweep

`inbox/` stays for a note its member did not ingest (no assistant, or by choice). The sweeper ({{SWEEPER}})
ingests each such note as in §2, moves it to `knowledge/sources/inbox/`, and keeps the note's member as
`by:` in its claim lines. `node tools/sync.js` names the notes waiting.

The sweeper also runs, now and then, the whole-memory checks — `node tools/claims.js`,
`node tools/verify-links.js` — and reads the pages changed since the last run for sentences that disagree:
each disagreement becomes a question to the members concerned, quoting both sentences; nothing is decided.
Tool proposals (AGENTS.md §7, second paragraph) are taken from the log.
