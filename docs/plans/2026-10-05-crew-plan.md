# Crew Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the crew (Voice, Lead, Architect, Builder, Scout, Sentry) as Joserah 0.18.0: config-driven agent definitions, the Ledger, the crew hooks, the Tracker Crew strip behind developer mode, and the prompt and skill text that make Voice only talk.

**Architecture:** A generator (`tools/crew.js`) writes five stamped agent definitions into each workspace's `.claude/agents/` from the `crew` config block. Lead's record is an append-only Ledger (`tools/ledger.js`) under `.joserah/desk/crew/YYYY-MM-DD/lead/`; a new payload-reading hook script (`hooks/crew.js`) creates it, stamps it at compaction and session end, and re-injects its open items after compaction. `tools/tracker.js` gains a `crew` subcommand and a strip that names the roles only when `devMode` is true (Task 3.7).

**Tech Stack:** Node.js (no dependencies), `node:test`, Claude Code plugin hooks (`hooks/hooks.json`, `"shell": "bash"`), static HTML Tracker pages.

**Spec:** `docs/specs/2026-10-05-crew-design.md` (read it with this plan; section names below refer to it).

## Global Constraints

- No personal data in the repository: no real names, companies, paths or credentials; placeholders are `{{UPPER_SNAKE}}` (CONTRIBUTING.md).
- Hooks are a single `command` string with `"shell": "bash"`, path quoted: `node "${CLAUDE_PLUGIN_ROOT}/hooks/x.js"`.
- `hooks/session-start.js` never reads stdin (its header says why); payload-reading work goes in `hooks/crew.js` with the idle-timer stdin read used by `hooks/tool-count.js`. Every hook path exits 0.
- Every change to `templates/AGENTS.md` bumps `<!-- joserah:prompt-version N -->` on line 1 (now 26 → 27) and keeps the file under 160 lines.
- A release bumps `.claude-plugin/plugin.json` `version`, `.claude-plugin/marketplace.json` `metadata.version` and `plugins[0].version` together (0.17.10 → 0.18.0) and adds a `## 0.18.0` CHANGELOG section.
- Crew defaults: Lead opus/medium, Architect opus/high, Builder opus/high, Scout sonnet/medium, Sentry haiku/low. Voice has no entry.
- `crew` absent means on with defaults; `"crew": false` or `"enabled": false` means off. `devMode` absent means false.
- Log location: `.joserah/desk/crew/YYYY-MM-DD/<role>/`; Ledger `lead/ledger-HHMM.md`.
- Ledger line: `HH:MM · <kind> · <job> · <text> · <log path or ->`, kind ∈ `open | decision | start | owner | end | compact | session-end`.
- Strip states `work | owner | idle`; owner reasons `decision | sign-in | connection | approval`.
- Role icons: Voice speech bubble, Lead brain, Architect compass, Builder wrench, Scout magnifier, Sentry shield; inline SVG line icons, 24×24, `stroke="currentColor"`, `fill="none"`, no emoji, no faces.
- Colours are calm: icons and strip use only the page's existing theme tokens, light and dark; no new hues.
- Row groups: optional `parent` = an existing row's title; set only when certain; one level; only finished work folds — an agent-working or owner row is never inside a `<details>`, it shows its main job's title as a small label (owner, 2026-10-05: "Aktif çalışan işler kapanabilir olmamalı." / "Yukarısı yani"); every fold closed by default, one open at a time; no `parent` anywhere renders byte-identical to before.
- Tests: `node --test tests/*.test.js` from the repo root, in Git Bash on Windows. Tests fix the clock with `JOSERAH_NOW`.
- Commit messages: English subject, blank line, signature line `<model> <effort> — Joserah <role>`; no Co-Authored-By.

## Review Focus

1. **A `crew` block with a typo** (`"scuot": {...}`, `"effort": "hgih"`): the generator must fail loudly naming the key, and doctor must report it, not silently run defaults. → Task 1.1 test `unknown role or effort is an error`.
2. **The owner's own `.claude/agents/lead.md`** (or `scout.md`) already exists, unstamped: never overwritten, reported once. → Task 1.3 test `an unstamped same-named file is kept and reported`.
3. **A Ledger line whose text contains ` · `** (the separator) or a newline: parsing must still find kind and job, and a newline must not create a second line. → Task 2.1 test `separator and newline in text`.
4. **Hook payload missing or malformed on stdin** (empty, not JSON, never closed on Windows): `hooks/crew.js` exits 0 within the idle timer and writes nothing. → Task 4.1 test `empty or broken payload is a silent no-op`.
5. **Two conversations on the same day** each with its own Lead: stamps and re-injection must go to the Ledger whose `open` line carries this session's id, never the other one's. → Task 4.2 test `stamp goes to the matching session only`.

```js
'use strict';
const ROLES = ['lead', 'architect', 'builder', 'scout', 'sentry'];
const EFFORTS = ['low', 'medium', 'high'];
const DEFAULTS = {
  lead: { model: 'opus', effort: 'medium' }, architect: { model: 'opus', effort: 'high' },
  builder: { model: 'opus', effort: 'high' }, scout: { model: 'sonnet', effort: 'medium' },
  sentry: { model: 'haiku', effort: 'low' },
};
function resolveCrew(cfg = {}) {
  const block = cfg.crew;
  const devMode = cfg.devMode === true;
  if (block === false) return { enabled: false, devMode, roles: clone(DEFAULTS) };
  const b = block && typeof block === 'object' ? block : {};
  for (const k of Object.keys(b)) {
    if (k !== 'enabled' && !ROLES.includes(k)) throw new Error(`crew: unknown role "${k}"`);
  }
  const roles = {};
  for (const r of ROLES) {
    const o = b[r] || {};
    const effort = o.effort ?? DEFAULTS[r].effort;
    if (!EFFORTS.includes(effort)) throw new Error(`crew.${r}: unknown effort "${effort}"`);
    roles[r] = { model: o.model ?? DEFAULTS[r].model, effort };
  }
  return { enabled: b.enabled !== false, devMode, roles };
}
const clone = (o) => JSON.parse(JSON.stringify(o));
module.exports = { resolveCrew, ROLES, EFFORTS, DEFAULTS };
```
