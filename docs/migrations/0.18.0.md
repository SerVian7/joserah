# 0.18.0 — the crew

Everything below describes what a workspace should **look like** at 0.18.0. A workspace created at
0.18.0 or later already looks like this and needs nothing here.

## Step 1 — the crew's agent definitions (a tool; nothing to decide)

The work now runs behind the scenes through a crew of five agents. Their definitions live in the
**workspace's** `.claude/agents/{lead,architect,builder,scout,sentry}.md`, written from config by:

```
node "${CLAUDE_PLUGIN_ROOT}/tools/crew.js" <workspace-root>
```

`/joserah:update` runs it after the prompt refresh (step 4b). Each written file carries a stamp line
(generated from config, do not hand-edit); a same-named file without the stamp is the owner's own and is
reported (`kept-owner <role>`), never overwritten. Workspace-own agents with other names (a `planner`, an
`archivist`, a `manager`) are left alone; if one overlaps a crew role, retiring it is the owner's call.
`node "${CLAUDE_PLUGIN_ROOT}/tools/crew.js" <workspace-root> --check` compares without writing, and doctor
runs the same check (`crew definitions current`).

**Restart, once, if the folder is new.** Claude Code watches `.claude/agents/` and applies a changed file
to the next delegation, but only when the folder existed when the session started. When this run created
`.claude/agents/` for the first time, say in one line that a restart is needed once. Every later
regeneration needs none.

## Step 2 — the optional `crew` block (nothing to migrate)

Crew is on by default; no block means on, with defaults. A workspace that wants other models or
efforts adds an optional `crew` block to `.joserah/config.json`:

```json
"crew": {
  "lead":      { "model": "opus",   "effort": "medium" },
  "architect": { "model": "opus",   "effort": "high" },
  "builder":   { "model": "opus",   "effort": "high" },
  "scout":     { "model": "sonnet", "effort": "medium" },
  "sentry":    { "model": "haiku",  "effort": "low" }
}
```

A missing role or field falls back to its default; an unknown role, field or effort is an error that
names the key. `"crew": false` (or `"enabled": false` inside the block) switches the crew off: the
workspace runs as before (the orchestrate skill as it stands, the Manager for waves), and `crew.js`
removes the definitions it wrote — only stamped ones. Every change to the block is followed by a
`crew.js` run.

## Step 3 — developer mode (nothing to migrate)

`devMode` is a top-level config key, **off by default**: absent means off. Off, the assistant never
names agents, roles or models to the owner and speaks of the work in the first person; the update's
own one line speaks of the work only. An owner who asks how the work is done, or asks to see it, is
told developer mode exists: `"devMode": true` names the crew in replies and on the Tracker's Crew strip.

## Step 4 — what stays as it is

- Manager waves in flight finish as they are; new work goes to the crew's Lead.
- Open Daily Trackers keep working: a `rows.json` without `crew` renders with no strip.
- The workspace's own `.joserah/directives.md` is never written. If one of its rules hands Tracker
  rows or page updates to subagents, it now conflicts with "Tracker rows and links are the main
  session's": point it out to the owner in one line; the owner amends it.

---

## When this is done

Stamp `migratedTo` at the installed version (`/joserah:update` step 3b has the command), then run
doctor. `crew definitions current` should be `ok` (or a `warn` naming the owner's own file under a
crew role name), and `structure migrations applied` should stop warning.
